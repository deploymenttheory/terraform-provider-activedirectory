# activedirectory_organizational_unit

Discovers organizational units for GUID import. The SDK materializes a bounded query; this is not an unbounded LDAP page stream.

Configure verified LDAPS using environment-delivered credentials:

```terraform
terraform {
  required_version = ">= 1.14.0"
  required_providers {
    activedirectory = { source = "deploymenttheory/activedirectory" }
  }
}

# Supply AD_HOST, AD_USERNAME, AD_PASSWORD and, for a private CA, AD_CA_CERT_PEM
# through your secret manager or process environment. Hostname/chain checks remain enabled.
provider "activedirectory" {
  auth_method = "simple"
  transport   = "ldaps"
}
```

## Minimal example

```terraform
list "activedirectory_organizational_unit" "example" {
  provider = activedirectory
  config {
    base_dn = "OU=Managed,DC=example,DC=com"
  }
}
```

## Extended example

```terraform
list "activedirectory_organizational_unit" "filtered" {
  provider         = activedirectory
  include_resource = true
  limit            = 100
  config {
    base_dn      = "OU=Managed,DC=example,DC=com"
    ldap_filter  = "(name=Terraform*)"
    scope        = "one_level"
    page_size    = 100
    result_limit = 100
  }
}
```

## Query and import

Keep the provider requirements in `providers.tf`; query files contain list/provider configuration,
not a `terraform` block. Run `terraform init`, then `terraform query -generate-config-out=generated.tf`
to produce GUID-based import configuration. Use each example variant separately.

The SDK materializes a bounded search before emitting rows. This is not an unbounded page stream.
The Terraform limit can lower the configured result bound. Duplicate or unusable identities,
cancellation and incomplete reads receive diagnostics; reaching the bound does not prove exhaustion.
Generated identities use exactly `{ id = "<object GUID>" }`, matching resource import.

See [HashiCorp's query-file guidance](https://developer.hashicorp.com/terraform/language/files/tfquery).
