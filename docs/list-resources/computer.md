# activedirectory_computer (List Resource)

Discovers computers for GUID import. The SDK materializes a bounded query; this is not an unbounded LDAP page stream.

```terraform
terraform {
  required_version = ">= 1.14.0"
  required_providers {
    activedirectory = { source = "deploymenttheory/activedirectory" }
  }
}

# Supply AD_HOST, AD_USERNAME, AD_PASSWORD and, for a private CA, AD_CA_CERT_PEM
# through your secret manager or process environment. Hostname/chain checks remain enabled.
provider "activedirectory" {
  auth_method = "simple"
  transport   = "ldaps"
}
```

```terraform
list "activedirectory_computer" "automation" {
  provider = activedirectory
  config {
    base_dn = "OU=Automation,DC=example,DC=test"
  }
}
```

```terraform
list "activedirectory_computer" "engineering" {
  provider         = activedirectory
  include_resource = true
  limit            = 100
  config {
    base_dn      = "DC=example,DC=test"
    ldap_filter  = "(operatingSystem=Windows*)"
    scope        = "subtree"
    page_size    = 100
    result_limit = 100
  }
}
```

Keep provider requirements/configuration in `providers.tf` beside the query file. The provider
performs a bounded SDK query when iteration starts, sorts by GUID, then respects cancellation
and consumer stop. It does not expose an unbounded LDAP page stream. Terraform's `limit` can
lower the configured result bound. Reaching the bound does not prove complete absence of more
matches, and failures retain usable observed identities without claiming search completion.

Identity is exactly `{ id = objectGUID }`. Resource snapshots contain observable typed fields
and no password. Historical password-version metadata cannot be discovered; generated/imported
resources start at zero. An unavailable required sAMAccountName prevents a managed snapshot.
Configuration generation does not authorize password resets or account enablement changes.
