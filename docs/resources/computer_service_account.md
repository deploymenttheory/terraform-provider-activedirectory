# activedirectory_computer_service_account (Resource)

Manage one direct computer/account link. Existing links are adopted; deletion removes only this link. Other accounts and both directory objects are preserved. No local installation, password retrieval or password-reader grants are performed.

The ordered identity is `computer GUID/service-account GUID`. Names and DNs may
change without changing identity. Endpoints must already exist. These operations
change directory links only: they do not install accounts locally, retrieve or
reset managed passwords, or grant permission to read gMSA passwords. This matches
[Add-ADComputerServiceAccount](https://learn.microsoft.com/en-us/powershell/module/activedirectory/add-adcomputerserviceaccount)
and [Remove-ADComputerServiceAccount](https://learn.microsoft.com/en-us/powershell/module/activedirectory/remove-adcomputerserviceaccount).

Create adopts an existing link or ensures that one association. Delete removes
only the owned link; both objects and other associations remain intact. Changing
either endpoint requires replacement. Do not manage the same pair in multiple
states or through a competing authoritative collection.

`is_associated` is true after positive observation. An omitted attribute cannot
distinguish an empty collection from denied visibility. Refresh retains the GUID
pair and null observed presence; an explicit apply can ensure the configured
link. Unresolved submitted effects retain recovery intent and block mutation
replay until fresh observations reconcile the same pair. No automatic rollback
or broad link reset is performed.

```terraform
terraform {

    activedirectory = { source = "deploymenttheory/activedirectory" }

# Supply AD_HOST, AD_USERNAME, AD_PASSWORD and, for a private CA, AD_CA_CERT_PEM
# through your secret manager or process environment. Hostname/chain checks remain enabled.
provider "activedirectory" {
  auth_method = "simple"
  transport   = "ldaps"
}
```

```terraform
resource "activedirectory_computer_service_account" "example" {
  computer_guid        = "11111111-1111-4111-8111-111111111111"
  service_account_guid = "22222222-2222-4222-8222-222222222222"
}
```

```terraform
# Each instance owns one link. Service accounts omitted from this set remain unmanaged.
resource "activedirectory_computer_service_account" "application_accounts" {
  for_each = toset([
    "22222222-2222-4222-8222-222222222222",
    "33333333-3333-4333-8333-333333333333",
  ])
  computer_guid        = "11111111-1111-4111-8111-111111111111"
  service_account_guid = each.value
}
```

An acknowledged atomic value deletion can finish even when the SDK reports its
specific omitted-final-attribute verification result. The provider reports a
warning about collection visibility. Transport uncertainty, joined failures,
partial effects and conflicting identities retain recovery intent instead.

## Schema

### Required

- `computer_guid` (String) Existing computer object GUID. Changing either endpoint replaces the owned link.
- `service_account_guid` (String) Existing standalone or group managed service-account object GUID.

### Read-Only

- `computer_dn` (String) Current observed computer distinguished name. Renames preserve link identity.
- `id` (String) Canonical computer GUID/account GUID composite identity.
- `is_associated` (Boolean) Whether the direct link was positively confirmed. Null means current visibility is indeterminate; an explicit apply ensures the configured link.
- `service_account_dn` (String) Current observed account distinguished name. Renames preserve link identity.
