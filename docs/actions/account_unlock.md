# activedirectory_account_unlock (Action)

Unlock one AD DS account on the selected DC by resetting lockoutTime to zero. Does not enable a disabled account or prove forest-wide convergence. Failed or uncertain submissions are never automatically retried.

Requires Terraform 1.14 or later. Select the account by GUID and acknowledge the exact DC DNS
name reported by the provider's RootDSE observation. A different server is refused before writing.

## Provider configuration

```terraform
terraform {
  required_version = ">= 1.14.0"
  required_providers {
    activedirectory = { source = "deploymenttheory/activedirectory" }
  }
}

# Credentials come from AD_USERNAME and AD_PASSWORD. For a private CA, set AD_CA_CERT_PEM.
provider "activedirectory" {
  host        = "dc.example.test"
  auth_method = "simple"
  transport   = "ldaps"
}
```

## Explicit invocation

```terraform
action "activedirectory_account_unlock" "unlock" {
  config {
    object_guid = "8b48ae8e-aea5-4c45-acef-b319f8db9cf4"
    server      = "dc.example.test"
  }
}

# Explicit invocation: terraform apply -invoke=action.activedirectory_account_unlock.unlock
```

## Explicit request through a lifecycle trigger

```terraform
variable "unlock_request" {
  type        = string
  description = "Explicit request identifier. Change this value only after verifying any earlier unlock outcome."
}

action "activedirectory_account_unlock" "requested" {
  config {
    object_guid = "8b48ae8e-aea5-4c45-acef-b319f8db9cf4"
    server      = "dc.example.test"
  }
}

resource "terraform_data" "request" {
  input = var.unlock_request

  lifecycle {
    action_trigger {
      events  = [before_create, before_update]
      actions = [action.activedirectory_account_unlock.requested]
    }
  }
}
```

Unlocking resets `lockoutTime` on the selected DC. It neither enables a disabled account nor
changes passwords, account policy or computed eligibility flags. A successful readback establishes
the same GUID and `lockoutTime=0` on that server; it does not establish forest-wide convergence.

The provider submits one SDK operation per invocation. It never retries a rejected or uncertain
write. On an accepted/uncertain failure, preserve the diagnostic's target GUID and DC and verify
that account independently before explicitly invoking again. A lifecycle trigger is a separate
invocation when its configured resource event occurs; do not use trigger changes as automatic
recovery from an unknown outcome. Actions have no managed resource state or import operation.
