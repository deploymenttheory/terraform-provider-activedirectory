# activedirectory_account_settings (Data Source)

Read existing account-control, expiration and computed status by explicit GUID or DN. Later reads are pinned to the resolved GUID; no account is created, changed or owned.

## Provider configuration

```terraform
terraform {
  required_version = ">= 1.14.0"
  required_providers {
    activedirectory = { source = "deploymenttheory/activedirectory" }
  }
}

# Supply AD_HOST, AD_USERNAME, AD_PASSWORD and, for a private CA, AD_CA_CERT_PEM
# through your secret manager or process environment. Hostname/chain checks remain enabled.
provider "activedirectory" {
  auth_method = "simple"
  transport   = "ldaps"
}
```

## GUID lookup

```terraform
data "activedirectory_account_settings" "example" {
  object_guid = "b591fb30-6292-4744-bf23-5f346cb74559"
}
```

## DN lookup and status

```terraform
# Separate read-only lookup by DN. Account settings are never changed by a data source.
data "activedirectory_account_settings" "by_dn" {
  dn = "CN=Existing Service User,OU=Service Accounts,DC=example,DC=com"
}

output "account_status" {
  value = {
    guid             = data.activedirectory_account_settings.by_dn.id
    enabled          = data.activedirectory_account_settings.by_dn.enabled
    never_expires    = data.activedirectory_account_settings.by_dn.never_expires
    expires_at       = data.activedirectory_account_settings.by_dn.expires_at
    locked_out       = data.activedirectory_account_settings.by_dn.locked_out
    password_expired = data.activedirectory_account_settings.by_dn.password_expired
  }
}
```

Supply exactly one of `object_guid` or `dn`. After resolving the first lookup, the SDK
expiration read is pinned to that account's GUID. Both complete unique identity observations
must agree; incomplete or contradictory identity results emit no usable snapshot.

Missing/hidden fields remain null rather than false or zero. `locked_out` and
`password_expired` reflect the selected DC's computed state, not forest-wide convergence.
`password_last_set` and `account_expires` are exact FILETIME outputs. `never_expires` is true
for either documented native never-expire representation; `expires_at` is a finite UTC
instant or null. This reads no password material, performs no login probe and changes nothing.
